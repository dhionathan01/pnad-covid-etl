Dos microdados do IBGE a um Data Warehouse em SQL Server

Carga dos microdados da PNAD Covid-19 (maio a novembro de 2020) com extração do CSV, validação linha a linha, staging, normalização e modelo estrela. Cada etapa grava log com linhas lidas, linhas gravadas e status.

7 arquivos mensais 23 colunas de origem 3 dimensões + 1 fato 20 functions 9 procedures SQL Server 2022 via Docker

Arquitetura

Tudo roda dentro do SQL Server. O staging do enunciado, desenhado no Oracle, ficou no schema staging do mesmo banco.

Estrutura do repositório

Functions e procedures

O SQL Server não tem PACKAGE. O schema etl cumpre esse papel e agrupa todas as rotinas do processo.

Procedures

ProcedureResponsabilidade
etl.usp_carregarLê o CSV com BULK INSERT, localiza as colunas pelo cabeçalho, valida, grava válidas na staging e inválidas em staging.pnad_covid_rejeitado. Reprocessar um mês substitui o anterior.
etl.usp_carregar_dim_tempoCombinações únicas de ano e mês, com o nome do mês, sem duplicar.
etl.usp_carregar_dim_municipioTraduz o código da capital, normaliza o nome e insere só os novos. Quem mora fora da capital vai para "Demais Municipios" da UF.
etl.usp_carregar_dim_pessoaFaixa etária, sexo em M/F e descrições de cor/raça, escolaridade e rendimento pelas functions. Insere só perfis novos.
etl.usp_carregar_fatoResolve as chaves, agrega as métricas e deixa fora da fato (e no log) qualquer linha sem chave. FKs garantem a integridade.
etl.usp_executar_pipelineRoda as etapas na ordem e registra em qual etapa parou, se parar.
etl.usp_limpar_cargaEsvazia staging, dimensões e fato para o teste. O log fica.
auditoria.usp_log_*Abrem e fecham a linha de log fora da transação, para o erro ficar registrado mesmo com ROLLBACK.

Validações da carga

Uma linha é rejeitada quando não dá para separar os campos, quando ano ou mês faltam ou o mês está fora de 1 a 12, quando a UF não existe, quando a idade falta ou passa de 0 a 130, quando o sexo não é 1 ou 2, quando a capital informada não é a da UF, ou quando um campo de código traz texto. O motivo fica gravado junto da linha original.

SUCESSO todas as linhas lidas gravadas SUCESSO PARCIAL parte rejeitada ERRO nada gravado ou falha

Como executar

Precisa de Docker e Git. Escolha o terminal que vai usar em casa.

  1. Configurar e subir o SQL Server

    Copie o .env e, se quiser, troque a senha.

    Copy-Item .env.example .env
docker compose up -d

  2. Criar banco, tabelas, functions e procedures

    Pode rodar de novo sempre que mudar um .sql.

    .\scripts\instalar.ps1

  3. Testar com o CSV pequeno

    Carrega 19 linhas (7 inválidas de propósito) e confere 28 resultados esperados.

    .\scripts\testar.ps1

  4. Baixar os microdados e carregar tudo

    Cerca de 80 MB compactados. Use -Meses 05 para baixar só um mês.

    .\scripts\baixar_dados.ps1
.\scripts\executar_pipeline.ps1

Conectar pelo SSMS ou Azure Data Studio

Servidor localhost,1433, usuário sa, a senha do .env e "confiar no certificado do servidor" marcado. Para um SQL Server instalado direto no Windows, rode os .sql de sql/ na ordem e chame etl.usp_carregar com o caminho do CSV no seu disco.

Decisões

Pontos em que o projeto interpreta ou complementa o enunciado.

Staging no SQL Server

O diagrama mostra Oracle, mas a disciplina é SQL Server. O staging virou um schema do mesmo banco, o que evita linked server.

Perfis na dim_pessoa

A PNAD não identifica a pessoa. A dimensão guarda combinações únicas de atributos e a fato soma quantas pessoas há em cada uma.

Município a partir de CAPITAL

O microdado só identifica a capital. Quem mora no interior entra como "Demais Municipios" da UF, sem perder a linha.

Colunas acrescentadas

nu_mes ordena e liga a dim_tempo. qt_pessoas dá a base dos percentuais. ID_LOG na staging liga cada linha à carga que a gravou.

Sem peso amostral

As métricas contam entrevistados. Para estimar a população seria preciso usar o peso V1032.

Leitura por nome de coluna

O cabeçalho define a posição de cada campo. Arquivos de meses diferentes carregam sem mudar código.
